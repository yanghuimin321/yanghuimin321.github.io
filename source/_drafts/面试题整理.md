1. js数据类型：

   |          | 基本（原始）数据类型                                         | 引用（对象）数据类型                                         |
   | -------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
   |          | Number,String,Boolean,Undefined,Null,Symbol,BigInt（ES2020新增） | Object，Array，Function，其他内置对象(如Date,RegExp,Map,Set) |
   | 存储方式 | 直接储存在**栈**内存中，占用空间固定                         | 存储在**堆**内存中，**栈内存中存储的是指向堆内存的引用(指针)** |
   | 访问方式 | **按值访问**，操作的是实际的值                               | **按引用访问**，操作的是对象的引用                           |
   | 复制行为 | 复制时，创建一个新的值，两者互不影响                         | 复制时，复制的是引用(地址)，两个变量指向同一个对象           |
   | 比较方式 | 比较的是值                                                   | 比较的是引用(内存地址)，即使两个对象内容相同，但引用不同，也不相等 |
   | 可变性   | 不可变。一旦创建，值就不能改变（变量可以重新赋值，但是值本身不变） | 可变。可以修改其属性和内容                                   |
   | 类型检测 | typeof：返回对应的类型字符串（除null返回object(历史遗留)）（ | typeof：除函数返回function，其余返回object；instanceof基于原型链可以检测对象具体类型 |
   |          | 每当用到某个原始值的方法或属性时，后台都会创建一个相应原始包装类型的对象，从而暴露出操作原始值的各种方法 |                                                              |

2. 闭包：引用了另一个函数作用域中变量的函数，通常是在嵌套函数中实现

3. 箭头函数不能使用的场景：**需要动态this，构造函数、方法定义的场景下不适用，适用于需要简单回调，固定this的场景**

   - **不能用作构造函数**：箭头函数没有[[construct]]方法，因此不能使用new关键字调用

   - 没有原型：箭头函数没有prototype属性

   - 不能绑定this：箭头函数的this值在定义时确定，并且不会改变。因此不能使用call/apply/bind来改变this指向

   - **不能用作生成器**：箭头函数不能使用yield关键字，因此不能作用生成器函数

   - **不能用于对象方法**：因为箭头函数的this会继承自外层函数，而不是指向调用它的对象。

   - **不能用于事件处理函数**：需要动态this指向触发事件的元素时，使用箭头函数会导致this指向不正确

   - **不能用于定义原型方法**：因为this不会指向实例

   - **不能用于需要使用 `arguments` 对象的函数**：箭头函数没有自己的arguments对象

   - **不能用于需要函数提升的场景**：函数声明会被提升，而箭头函数（作为函数表达式）不会被提升。

4. 浏览器事件循环：

   - 浏览器进程：浏览器主进程，GPU进程，网络进程，插件进程，渲染进程（通过IPC进行进程间信息传递）
   - 渲染进程：GUI渲染线程、js引擎线程（和GUI互斥阻塞），事件触发线程，定时器触发线程，异步http请求线程
   - js引擎执行同步代码(调用栈)，遇到异步操作（如点击事件、定时器、网络请求），交由对应的其他线程处理，这些线程完成任务后，将回调函数放入任务队列，事件触发线程监控调用栈，一旦栈空，就将队列中的回调按规则（分微任务、宏任务）取出，交给JS引擎执行。
   - 像Promise.then、MutationObserver这类微任务，其回调是由JS引擎自身在执行同步代码后直接放入微任务队列的，不经过其他线程。
   - 宏任务：定时器、UI渲染、用户交互事件、主线程的同步脚本代码、I/O操作
   - 微任务：promise.then/catch/finally，MutationObserver（浏览器）、queueMicrotask()（node）

5. 从输入网址到页面显示的过程：

   1. DNS解析：DNS优化（DNS缓存，DNS负载均衡）
   2. 发起TCP连接
   3. 发送HTTP请求（HTTPS的加密协议：TLS，传输层之上，应用层之下）
   4. 服务器处理请求并返回HTTP报文
   5. 浏览器解析渲染页面：
      - 处理HTML并构建DOM树，处理CSS构建CSSOM树(样式计算(DOM样式))，将DOM与CSSOM树合并成一个渲染树(布局树)，根据渲染树布局计算每个节点的位置，调用GPU绘制合成图层显示在屏幕上
      - 构建CSSOM树时会阻塞渲染，直至CSSOM树构建完成
      - HTML解析script标签时，会暂停构建DOM，完成后才会从暂停的地方开始继续构建；只有当解析完样式表才会执行 JS，所以CSS 也会导致暂停构建 DOM
      - Load 和 DOMContentLoaded：
        - Load 事件触发代表页面中的 DOM，CSS，JS，图片已经全部加载完毕。
        - DOMContentLoaded 事件触发代表初始的 HTML 被完全加载和解析，不需要等待 CSS，JS，图片加载
      - 图层：以把普通文档流看成一个图层。特定的属性可以生成一个新的图层。不同的图层渲染互不影响，所以对于某些频繁需要渲染的建议单独生成一个新图层，提高性能。但也不能生成过多的图层，会引起反作用（3D 变换，`video`、`iframe` 标签，`position: fixed`）
      - 回流、重绘、合成
   6. 连接结束

6. v-model：

   - 默认使用在表单元素中，绑定value的prop和input事件(除select元素是change)，.lazy修饰符可以让其绑定的事件变为change
   - 可以使用在非表单元素(自定义元素)，通过defineModel，底层原理是绑定modelValue的prop和update:modelValue事件；通过传参可以改变绑定的prop属性，或者使用多个v-model；通过修饰符可以在获取到modifiers，在defineModel中传参设置get、set方法来对绑定数据做修改

7. v-for：就地更新的策略（不依赖子组件状态或者临时 DOM 状态 (例如表单输入值) 的情况）

   - key：为了跟踪每个节点的标识，从而重用和重新排序现有的元素（作为 Vue 的虚拟 DOM 算法提示，在比较新旧节点列表时用于识别 vnode）
   - 不建议使用index作为key：index值不稳定，主要在列表插入/删除项时，可能导致渲染错乱和组件状态丢失

8. vue2和vue3的区别：

   1. 架构与核心机制的升级：
      1. 响应式系统重写：
         - Vue2： 使用 Object.defineProperty 递归劫持对象属性的 getter/setter。对新增/删除属性不敏感（需用Vue.set/$delete），对数组需要通过重写方法拦截。
         - Vue3： 使用 Proxy 代理整个对象。能原生监听属性的增删、数组索引/长度变化，性能更好，代码更简洁。这是性能提升和更好的TypeScript支持的基础。
      2. 编译优化：
         - Vue2： 虚拟DOM的Diff是全量对比
         - Vue3： 引入 PatchFlag（静态标记） 和 Tree Shaking（按需编译）。编译器能标记出模板中的动态部分，在Diff时只对比这些动态节点，极大提升了渲染效率。同时，未使用的模块（如v-model指令）在打包时会被摇树优化掉，体积更小。
      3. 代码组织与复用范式的革新：
         - Vue2（Options API）：逻辑通过 data, methods, computed 等选项分散组织。在复杂组件中，相关逻辑被割裂，阅读和维护困难。
         - Vue3（Composition API）：使用 setup() 函数和一系列组合式函数（如 ref, reactive, computed, watch），允许你将同一功能的逻辑组织在一起。这带来了更好的逻辑复用（自定义Hook）、更灵活的代码组织和完美的TypeScript类型推断支持。
      4. 声明周期和API命名：
         - 大部分生命周期函数前加了 on 前缀（如 mounted -> onMounted），且只能在 setup() 中使用
         - 全局API改为按需导入（如 Vue.nextTick -> import { nextTick } from ‘vue’），利于Tree Shaking。
   2. 开发体验与语法细节的改进：
      - 更好的TypeScript支持：从源码到API设计都为TS打造，提供完整的类型推断。
      - 多根节点组件（Fragment）：组件模板不再强制要求单一根元素。
      - Teleport组件：可将子组件“传送”到DOM中任何位置（如模态框、弹窗），解决嵌套定位问题。
      - v-model的增强：支持多个 v-model（如 v-model:title），并自定义修饰符。
      - v-for 与 v-if 优先级：Vue2中v-for更高，Vue3中v-if更高。

9. 防抖节流：

   1. 防抖：

      - 在某个事件频繁触发时，延迟一定时间后再执行回调函数。如果在延迟时间内又触发了同样的事件，那么会重新计时。从而避免了频繁触发回调函数，只在事件停止触发后执行一次

      - 使用场景：输入框搜索建议、窗口大小调整、按钮防重复点击

      - ```js
        function debounce(fn, delay,immediate){
            let timeId,result;
            return function(){
                var context = this
                var args = arguments
                if(timeId) clearTimeout(timeId);
                if(immediate){
                    let callNow = !timeId;
                    timeId = setTimeout(function(){
                        timeId = null;
                    },delay)
                    if(callNow) result = fn.apply(context, args)
                }else{
                    timeId = setTimeout(function(){
                        result = fn.apply(context, args)
                    },delay)
                } 
                return result;
            }
        }
        ```

   2. 节流：

      - 在某个事件持续触发时，限制一定时间间隔只执行一次回调函数

      - 使用场景：页面滚动加载、频繁点击按钮

      - ```js
        function throttle(fn, delay){
            let pretime = Date.now();
            return function(...args){
                var context = this
                var args = arguments
                if(Date.now() - pretime > delay){
                    fn.apply(context, args)
                    pretime = Date.now()
                }
            }
        }
        ```

        

10. 图片的预加载和懒加载：

    1. 预加载：预加载就是提前加载需要用到的图片素材，在用户需要用的时候可以直接从本地缓存中获取并渲染
       - 会增加服务器前端的压力，但是换取了更好的用户体验，用户的操作可以得到最快的反映
       - 实现方式：css方式（设置background属性url()），js方式(通过new Image对象设置src属性)
    2. 懒加载：延迟加载、按需加载。当图片出现在浏览器的可视区域内时，让图片显示出来。
       - 对服务器前端有一定的缓解压力的作用
       - 实现方式：
         1. 元素的getBoundingClientRect方法，返回一个DOMRect对象，包含元素的大小及其相对于视口的位置（监听scroll事件，配合节流进行加载）（兼容性好）
         2. IntersectionObserver API 交叉视口：监听某个元素是否出现在视口中（IE不支持）
         3. VueUse中useIntersectionObserver方法
         4. 浏览器原生支持属性：loading="lazy"

11. 浏览器缓存：优先级：Service Worker>强缓存>协商缓存>Web Storage

    1. 强缓存：`HTTP1.0`版本，使用的是Expires，`HTTP1.1`使用的是Cache-Control

    2. 协商缓存：由 `Last-Modified` / `If-Modified-Since` 和 `ETag` / `If-None-Match` 这两对响应头/请求头字段控制（协商缓存是在强缓存失效后触发）（强缓存与协商缓存的控制权，完全掌握在服务器手中，通过HTTP响应头传递给浏览器）（如果强制缓存未命中，但是协商缓存可用，则会向服务器发送条件请求，询问资源是否更新，如果返回304，则直接使用缓存）

    3. Web Storage缓存：

       1. LocalStorage：本地存储的公共资源，以页面域名划分的；

          sessionStorage：只存储到特定的会话中，不属于持久化的存储，所以关闭浏览器会清除数据

    4. Service Worker缓存：配合fetch事件拦截和 `Cache API`

    5. Cookie：每次HTTP请求都会自动携带在请求头中（同域下），因此会增加请求大小。其内容可由服务器通过 Set-Cookie 响应头设定，也可由客户端JavaScript（document.cookie）读写。

12. 网络安全：

    1. XSS（跨站脚本攻击）：
       - 攻击者将恶意代码“注入”到网页中，使其他用户的浏览器执行这段代码
       - 如何防御：对输入进行过滤和转义、设置 HttpOnly Cookie
    2. CSRF（跨站请求伪造）：
       - 攻击者欺骗用户的浏览器，以其身份向一个用户已认证的网站发起非预期的恶意请求。
       - 如何防御：生成token在请求时进行验证、验证请求来源（`Origin` 或 `Referer` 请求头）

13. 浏览器加载资源的优先级：

    - css文件同步加载：不阻塞html文件的解析
    - js同步文件：阻塞html文件的解析，但是由于可能使用css，所以需要在它之前的css文件加载完成后才处理，所以可能导致css文件阻塞html文件解析的样子
    - 图片一般异步请求：不阻塞解析和渲染
    - css文件如何异步加载：
      1. media属性不匹配当前环境，加载onload时再修改成匹配的：兼容性好，但是可能会fouc样式闪烁，需要js配合处理
      2. link标签preload，加载onload后改成样式表：需要polyfill
      3. js动态插入：完全控制加载时机，但是可能增加js复杂度
      4. 构建工具配置：组件级css随组件代码分隔异步加载
